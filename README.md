# 🌸 Nati Diet Tracker — יומן תזונה אישי

אתר רספונסיבי בעברית, מימין לשמאל, עם תפריט בן 4 ארוחות, בחירת מזונות מתוך כל קבוצות התחליפים, שמירה לפי יום, **מד צעדים יומי עם יעד 10,000 ומד מים של 3 ליטר**, יומן חודשי, שקילות בימי חמישי, מעקב היקפים ו**שיתוף התקדמות בהסכמה**.

**הגרסה המלאה נבנתה ב־React + Vite + Supabase.** היא מיועדת להרצה במחשב ולפרסום כאתר בטלפון. הקוד מוכן להפעלה, אך צריך להגדיר פרויקט Supabase ומפתח ציבורי כדי לשמור נתונים בענן. לא הועלה אתר חי ולא נוצר מסד נתונים בשם המשתמשת.

## התחלה — חיבור Supabase (פעם אחת)

1. צרי חשבון ופרויקט חדש ב־https://supabase.com/dashboard .
2. מתוך הפרויקט, עברי ל־**SQL Editor** → **New query**. פתחי את `supabase/schema.sql`, הדביקי **את כל** הקוד והפעילי **Run**. זה יוצר את הטבלאות, הרשאות הקריאה והכתיבה (Row Level Security), מנגנון יצירת פרופיל, ומנגנון קבלת הזמנת שיתוף.
3. בתוך Supabase: **Authentication → Providers → Email**. השאירי **Confirm email** פעיל. כך משתמשת צריכה לאמת את האימייל שלה לפני שתקבל שיתוף. ניתן להגדיר בהמשך SMTP מותאם לשליחת מיילים בכמות גדולה. 
4. ב־**Project Settings → Data API** העתיקי את **Project URL**. ב־**Project Settings → API Keys** העתיקי **publishable key** (או `anon` legacy key). **לעולם אל תעתיקי מפתח `service_role` או secret ללקוח.**
5. העתיקי את `.env.example` ושמרי בשם `.env` בתיקיית הפרויקט. הדביקי:

   ```env
   VITE_SUPABASE_URL=https://your-project.supabase.co
   VITE_SUPABASE_ANON_KEY=sb_publishable_your_key
   ```


### אם כבר הקמת את הפרויקט לפני עדכון הצעדים

**אין צורך למחוק את מסד הנתונים או להריץ מחדש את כל קובץ הסכמה.** ב־Supabase → SQL Editor פתחי את הקובץ `supabase/2026-11-01_add_steps.sql`, הדביקי והריצי. הוא יוסיף טבלת צעדים פרטית וימנע כפילות אם תריצי שוב. לאחר מכן העלי את הגרסה החדשה לריפוזיטורי, כדי ש־Vercel יבנה מחדש את האתר. אם זו הקמה חדשה, `schema.sql` כבר כולל את הצעדים ואין צורך להריץ את קובץ העדכון בנפרד.

### עדכון גרסה 1.1 (מים + קלוריות)

אם **כבר הגדרת חשבונות ונתונים ב־Supabase** (למשל שני משתמשים), יש לבצע עדכון נקודתי: הריצי ב־SQL Editor רק את `supabase/2026-11-01_add_water.sql` ולא את הסכמה המלאה. לאחר מכן העלי ל־GitHub את קוד הגרסה החדשה. הסכומים של הקלוריות נשמרים בתוך שדה ה־JSON הקיים של הארוחות, ולכן **לא נדרשת מיגרציה נוספת לקלוריות**. כל ההוראות נמצאות ב־`UPDATE-GUIDE-HE.md`.

**שימוש במים:** בתפריט היומי הזיני כמות כוללת במ״ל או השתמשי בכפתורי +250 / +500 / +1,000, ואז לחצי ״שמירת מים״. 3,000 מ״ל ומעלה = עמידה ביעד. הכמות מופיעה גם בלוח השנה. המים נשארים פרטיים לחשבון.

**שימוש בקלוריות:** סכום מנות התחליפים מוצג בכל ארוחה מול היעד ובסיכום היומי, אבל זה **אומדן לפי קבוצת מזון**. אפשר להזין מספר ידני מדויק יותר לכל ארוחה; שינוי בחירת מזון יאפס את הערך הידני. ארוחה תיחשב מלאה רק כאשר כל המרכיבים החיוניים של התפריט נבחרו, ולא רק מזון אחד.

**סימון ירוק ביומן:** 4 ארוחות מלאות + 10,000 צעדים לפחות; המים מוצגים בנפרד ואינם תנאי. אין שינוי בתנאי שמירת פרופיל ובשיתוף הפרטי.

**שימוש בצעדים:** בתפריט היומי, מתחת להתקדמות בארוחות, הזיני את מספר הצעדים לפי הטלפון או השעון ולחצי על **שמירת צעדים**. 10,000 צעדים או יותר = ״עמדת ביעד״. פחות מ־10,000 = ״עדיין לא הגעת ליעד״; בלי נתון = ״טרם הוזנו צעדים״. הנתונים נשמרים לכל תאריך בנפרד ומופיעים גם ביומן החודשי. בשלב זה **אין סנכרון אוטומטי עם Apple Health או Google Fit**. נתוני הצעדים פרטיים לחשבון ואינם נכללים בהזמנת השיתוף של משקל/היקפים.

## הפעלה מקומית (Windows / Cursor / VS Code)

התקיני Node.js LTS אם לא מותקן. פתחי את תיקיית `nati-diet-tracker` ב־Cursor, בחרי Terminal → New Terminal והריצי:

```bash
npm install
npm run dev
```

פתחי בדפדפן את הכתובת שמוצגת ב־Terminal, בדרך כלל `http://localhost:5173`.

**מפתח ה־publishable הוא ציבורי**, ולכן מצופה שייכלל בקוד הדפדפן לאחר בנייה. ההגנה על הנתונים מתבצעת ב־RLS שבמסד הנתונים. לעומת זאת, מפתחות `service_role` ו־secret אסור לשים שם.

## העלאה לאינטרנט ב־Vercel

1. פתחי ריפוזיטורי חדש ב־GitHub והעלי אליו את תיקיית הפרויקט (בלי `.env`, `node_modules` או `dist`).
2. ב־https://vercel.com/new בחרי **Import Git Repository**, בחרי את הריפוזיטורי. Vercel תזהה פרויקט Vite.
3. הגדרות: Framework **Vite**, Build command `npm run build`, Output directory `dist` (בדרך כלל מזוהים אוטומטית).
4. בתוך Vercel → Project → **Settings → Environment Variables** הוסיפי `VITE_SUPABASE_URL` ו־`VITE_SUPABASE_ANON_KEY` עם הערכים מפרויקט Supabase. הגדירי לכל סביבות ה־Deployment שבהן תרצי להשתמש. בצעי Deploy/ Redeploy לאחר שינוי משתנים.
5. לאחר קבלת כתובת האתר, חזרי ל־Supabase → **Authentication → URL Configuration**. הגדירי `Site URL` לכתובת הקבועה `https://YOUR-SITE.vercel.app` והוסיפי אותה לרשימת Redirect URLs. הוסיפי גם `http://localhost:5173` לפיתוח מקומי. האימות במייל והאיפוס צריכים להפנות לאתר המורשה.
6. פתחי את הקישור מכל מכשיר, צרי חשבון, אמתִי את האימייל, והתחברי. אפשר לשמור אייקון למסך הבית דרך Safari → Share → Add to Home Screen באייפון, או ב־Chrome באנדרואיד.

**חשוב:** עד שפרויקט Supabase והפרסום יוגדרו, האפליקציה לא תוכל לשמור לענן או לאמת משתמשות. הקבצים לבד אינם אתר חי.

## שיתוף נתונים — התנהגות ופרטיות

1. כל חשבון רואה את הארוחות, המשקל וההיקפים של עצמו בלבד כברירת מחדל.
2. משתמשת א׳ נכנסת ל־**שיתוף התקדמות**, מזינה אימייל של משתמשת ב׳, מסמנת האם לשתף משקל, היקפים או שניהם ולוחצת על יצירת הזמנה.
3. המערכת **אינה שולחת מייל אוטומטית**. א׳ שולחת לב׳ את קישור האתר ב־WhatsApp/מייל. ב׳ נרשמת או מתחברת עם אותה כתובת מייל, נכנסת ל־**שיתוף התקדמות** ומאשרת את ההזמנה.
4. רק לאחר האישור תופיע לב׳ תצוגת ההתקדמות שהוגדרה. **הארוחות והצעדים לא משותפים אף פעם** בגרסה זו.
5. א׳ יכולה לשנות הרשאות לצפייה במשקל/היקפים או לבטל שיתוף בכל רגע. אין אפשרות למחוק מרחוק עותק שב׳ כבר שמרה או צילמה כשהייתה לה גישה.
6. קבלת הזמנה מוגנת בפונקציית שרת שמוודאת שהאימייל המאומת של המחוברת תואם לאימייל ההזמנה. להבטחת ההתאמה יש להשאיר Confirm email פעיל.

## תמיכה בשימוש אישי / עלויות

## הערות על רשימת המזונות

- הרשימות מבוססות על התפריט שהמשתמשת סיפקה, ללא אימות תזונתי עצמאי. פריטים עם `/` הופרדו לבחירות לפי האפשרויות כפי שהתבקש. טווחי הקלוריות משוערים, ומותגים שונים עשויים להשתנות.
- למשל, שורת הביצים ב״חלבון גדול״ לא ציינה מספר ביצים שלמות; לא ניחשנו. שורות עם כמות חריגה מסומנות כהעברה מהמקור.
- ארבע הארוחות מסתכמות **על פי הכותרות** ב־1,200 קק״ל. אין חישוב בפועל של קלוריות לפי מוצרים. יש לבדוק עם תזונאית אם ההגדרות, מנות השמן והכמות הקלורית מתאימות, במיוחד סביב היריון/ניסיונות להרות.
- בחירת המזונות נשמרת אוטומטית; משקל והיקפים נשמרים בלחיצה על ״שמירה״. אם אין רשת, הנתונים החדשים לא נשמרים ויש לנסות שוב.

## בדיקות מומלצות לפני שימוש אמיתי

1. יצירת שתי משתמשות באימיילים שונים, אימות וכניסה.
2. שמירת ארוחות וצעדֵי יום ב־1.11 וב־2.11 (למשל 9,999 ו־10,000), סגירת דפדפן, פתיחה מחדש ופתיחת היומן. ודאי שרק 10,000 ומעלה מקבלים ✓.
3. יצירת שקילת פתיחה ושקילה ביום חמישי + מדידות היקפים ובדיקת גרפים.
4. וידוא שמשתמשת ב׳ לא רואה את נתוני א׳ לפני אישור הזמנה.
5. שליחת הזמנה לשיתוף משקל בלבד: וידוא שמשקל נגיש, היקפים וארוחות אינם נגישים. אחר כך שינוי הרשאות וביטולן.
6. בדיקת רספונסיביות באייפון/אנדרואיד, והורדת קובץ גיבוי.

> **סטטוס בדיקות בסביבת הכנת הקבצים:** בוצעה בדיקת תחביר לקובצי JavaScript/JSX. לא בוצעו בניית `npm install` מלאה, חיבור למסד נתונים אמיתי או בדיקות E2E של ההרשאות, מפני שלא הוגדר פרויקט Supabase ולא הייתה גישה לחבילות npm בסביבה. יש לבצע את הבדיקות לעיל לפני חשיפת נתונים אישיים אמיתיים.
